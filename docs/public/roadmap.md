# OPL 路线图

路线图只描述长期产品方向，不记录 sprint、完成流水或动态状态。

## Base

- 保持通用 Stage/Attempt、Workspace、Package 和 runtime substrate 简单稳定；
- 继续从真实 caller 中抽取通用能力，不提前平台化；
- 让 failure、recovery、evidence 和 owner action 对用户可理解。

## App

- 提供低认知负担的工作、文件、Agent 和 Settings 体验；
- 让安装、连接、恢复和升级形成真实 user path；
- 通过统一 contract消费 Framework，不建立第二 runtime/currentness。

## Packages

- 让专业 Agent 与 capability 即装即用，同时保留 domain authority；
- 只有真实跨仓 consumer 和独立 release cadence 出现后才晋升 repo/publication；
- 让 owner descriptor、native carrier、Host contribution 和 App view 形成可验证纵向链。

## Cloud

- 提供远端 workspace、managed resource、协作和跨设备 continuity；
- Cloud resource truth 与 local Framework/App projection保持清楚 owner；
- public service、security、billing 和 operations 由 Cloud product 独立验收。

## 质量标准

路线推进以可运行交付、owner readback 和真实用户路径为准。contract、测试、计划或文档本身不能替代 installed、release、domain acceptance 和 production evidence。
