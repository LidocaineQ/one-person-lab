# OPL 任务版图

本文只定义 OPL 面向用户的知识工作类型和典型交付物，不维护 Agent 成员、workstream 状态或实现计划。

## Research Ops

从研究问题、数据与证据到可审阅论文：

- cohort/data readiness；
- analysis、validation 和 sensitivity；
- evidence synthesis；
- manuscript、figure、table 和 submission package。

专业 truth、统计结论和 publication verdict 归研究 domain owner。

## Grant Ops

从资助机会与研究基础到可提交申请：

- opportunity fit；
- aims、strategy 和 work package；
- budget、timeline 和 risk；
- internal review 和 submission package。

fundability 和提交决定归申请负责人。

## IP Ops

从技术线索到知识产权材料：

- novelty 与 prior-art evidence；
- invention disclosure；
- claim/implementation support；
- attorney handoff。

法律判断和正式提交由有权负责人完成。

## Award Ops

从成果证据到奖项申报：

- eligibility；
- contribution narrative；
- impact evidence；
- nomination package。

资格和最终申报由 owner确认。

## Thesis Ops

从课题范围到学位论文和答辩材料：

- chapter plan；
- evidence and methods consistency；
- manuscript integration；
- defense package。

学术责任和正式提交由学生、导师和学校流程持有。

## Review Ops

对论文、项目、产品或 evidence package 做独立审阅：

- claim/evidence integrity；
- methodology and risk；
- reproducibility；
- revision route。

review 结论保持 reviewer identity，不能被执行 Agent覆盖。

## Presentation Ops

从内容目标到可演示、可讲授的视觉交付：

- storyline；
- slide/figure composition；
- visual QA；
- delivery assets。

内容 owner 与演讲者决定最终采用。

## Agent Foundry

Agent Foundry 是支撑上述工作类型的工程能力，不是第八类专业交付。它负责 blueprint、scaffold、evaluation、version 和 activation；目标 Package owner负责采用、发布和专业边界。

## 共同运行方式

所有任务类型共享 Workspace、Stage/Attempt、artifact-first progress、独立 review、owner receipt/typed blocker 和 human gate。它们可以使用不同 Agent、Package、模型和工具，但不改变 [运行模型](./operating-model.md) 的 authority 分工。
